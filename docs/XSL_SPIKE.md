# XSLスタイルシート方式 スパイク検証結果

検証日: 2026-07-28
検証コード: 使い捨て（`src/` は未変更。scratchpad 配下で実施し破棄済み）

## 結論（先に要約）

- PMDA公式XSLは **lxml だけで動く**（追加依存なし）。項番・見出し・表構造も
  高い忠実度で再現できる。**方式としては採用可能**。
- ただし2つの無視できない課題が見つかった:
  1. **PMDA公式XSL自体に浮動小数点バグがある**（項番が `9.199999999999999` になる）。
     自前の後処理で丸めが必須。
  2. **変換速度が遅い**（実測 約1秒/ファイル）。18,023件全件では
     **単純直列で約5時間**。現行パイプラインの「全件ロード約30秒」から
     大幅な劣化になるため、並列化前提で設計し直す必要がある。
- 図表画像は一括DLデータに**実在する**（`.gif`/`.jpg`、XMLと同じディレクトリ）。
  ただしXSLが期待するパスは `figures/<ファイル名>` で、実ファイルは
  サブディレクトリなしに直置きされている。パス変換が必要。

## 重大な発見1: PMDA公式XSLの浮動小数点バグ

`UseInSpecificPopulations`（9. 特定の背景を有する患者に関する注意）配下の項番が、
4サンプル**全件で再現**して壊れている:

```
9.199999999999999   ← 本来は 9.2（腎機能障害患者）
9.699999999999999   ← 本来は 9.7（小児等）
9.800000000000001   ← 本来は 9.8（高齢者）
```

これは `preview-include.xsl` 内で `concat($index, '.', $startIndex+position()-1)` の
ような浮動小数点演算をしているために生じるXSLT/EXSLT実装依存のIEEE754誤差。

**本実装後の目視突合で確認**: PMDA公式サイト
（`https://www.info.pmda.go.jp/go/pack/3219001X1138_1_03?view=body&lang=ja`）
では `9.2` `9.7` `9.8` と**正しく表示されており、バグは現れない**。
おそらく公式サイトはJS（`preview.js`）側で表示直前に丸めるか、サーバー側で
別途正規化した値を使っている。**四捨五入で丸める本実装の後処理
（`fix_float_section_no`）は、公式サイトの表示と一致する**ことを確認済み
（切り捨てだった場合は `9.1` になり不一致だった）。

対応: 後処理で「小数点以下が5桁以上同じ数字が続く」パターンを検出し、
`round(x, 1)` で丸める。**切り捨てではなく四捨五入が必須**
（`9.199999999999999` は `9.1` ではなく `9.2` が正）。試作コードで実装し、
4サンプルで正しい丸め (`9.2` `9.7` `9.8`) を確認済み。

## 重大な発見2: クロスリファレンスリンクの本文はJSが埋める

`<a class="HeaderRef" href="#HDR_XXX"></a>` という中身が空のリンクが、
条文中の相互参照箇所に大量に埋め込まれている。
このリンクの表示文言は XSLT ではなく `vendor/pmda-styles/js/preview.js`
（「見出し参照のテキスト挿入」）がブラウザ上で埋める:

- 文書末尾の `<div id="Header-data">` から `[data-header-id=<ref>]` のテキストを引く
- 見つかれば `［10.2 参照］`、見つからなければ `（見出し参照切れ）` に置換する

これらの間に区切りの読点（`,`）がテキストとして直接埋め込まれているため、
アンカーを空のまま残すと孤立したカンマが残る:

```
高カルシウム血症の患者[症状が悪化するおそれがある。],,
```

### 却下した対応: 要素をtailごと削除する

初期の試作では `a.HeaderRef` を **tail ごと**削除してカンマを消していたが、
これは誤り。実XSLT出力で確認すると tail は区切り記号とは限らず、
続く本文そのものが入る:

```html
<p>効能本文。出血のおそれがある<a class="HeaderRef" href="#HDR_Warnings"></a>。用法の図<img src="figures/fig001.gif">を参照すること。</p>
```

tail ごと削除すると `。用法の図` が丸ごと消え、次の出力になる（本文欠落）:

```
効能本文。出血のおそれがある![図](fig001.gif)を参照すること。
```

### 採用した対応: preview.js と同じ解決をPython側で行う

`render_xsl.resolve_header_refs()` が `Header-data` の対応表を引いて
アンカーにテキストを埋める。カンマは参照文言の区切りとして自然に収まる:

```
効能本文。出血のおそれがある［1. 参照］［2. 参照］。用法の図![図](fig001.gif)を参照すること。
```

## スキーマ案（実データに基づく更新）

計画時点の案から変更なしで通用することを確認:

```sql
CREATE TABLE sections (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    medicine_id INTEGER NOT NULL,
    ord         INTEGER NOT NULL,     -- 文書内出現順
    xml_id      TEXT,                 -- 'HDR_ImportantPrecautions' 等。空の場合あり
    section_no  TEXT,                 -- '9.2' 等。浮動小数点誤差を丸め済み
    heading     TEXT,                 -- '重要な基本的注意'（項番を除いた文言）
    level       TEXT,                 -- data-level 属性値（'1'〜'4', '99'=無階層）
    body_md     TEXT,                 -- Markdown化した本文
    FOREIGN KEY (medicine_id) REFERENCES medicines(id) ON DELETE CASCADE
);
```

- `level` は `INTEGER` ではなく `TEXT` にすべき（`99` は「階層なし」を表す番兵値で、
  数値として比較すると意味を持たないため文字列のまま保持し、必要ならアプリ側で解釈する）
- `xml_id` はネスト最下層で空になるケースがあるため `NOT NULL` にしない

## 本実装後に解決・確認した論点（追記: 2026-07-28）

1. **変換速度対策**: `multiprocessing.Pool`（28コア中27ワーカー）で解決。
   実測 18,023ファイルで**約27分**（1614秒）、成功18,005件・失敗18件
   （すべて `GenericName` を持たない特殊製剤: 血液バッグ、生理食塩液等）。
2. **公式サイトとの目視突合**: 実施済み。「「山善」第二リン灰」の
   禁忌セクション・併用注意の表・9.x系の項番すべてで完全一致を確認。
   なお**公式サイトでは浮動小数点バグは表示されない**（`9.2` `9.7` `9.8`
   と正しく出る）— 本実装の四捨五入処理は公式サイトの表示と一致する。
3. **画像パス解決**: `html_to_markdown._fix_img_src()` で `figures/` を除去。
4. **重複排除問題**: `package_insert_no` を一意キーにする方式で解決。
   実データでは 18,023 XML → **medicines 11,396件**（500件サンプルの実測比率
   ≒65.7%と整合）。旧方式の9,888件より本文カバレッジが大幅に改善。
5. **FTS5トークナイザ**: `trigram` を採用、実データで動作確認済み
   （`sections_fts` 820,378件、カバレッジ100%）。3文字未満ヒットしない制約は
   引き続き有効（運用ドキュメントに記載済み、`CLAUDE.md`参照）。

## 本実装で追加発見したバグ（スパイクでは検出できなかったもの）

- **`manufacturer` 抽出の既存バグ**: 旧 `json_to_db.py:extract_manufacturer`
  は実在しないタグ名 `ManufactAndImporter` を探しており（実際は
  `Manufacturer`）、常に一致せずフォールバックの全文抽出
  （`TypeOfIndustry`+`Name`+`Address`の連結）を返していた。
  `xml_to_db.py` で正しいタグ名に修正。
- **再実行時の重複挿入**: `insert_medicine` が既存medicineのIDを返した場合でも
  `interactions`/`sections`を無条件に再挿入していた
  （`specifications`はUNIQUE制約で保護されていたが他は無保護）。
  `is_new`フラグを追加し、新規作成時のみ挿入するよう修正。
  ロード処理が中断・再実行されるケースで顕在化する。
- 実ページとの目視突合を本実装のマイルストーンとして必須にする
